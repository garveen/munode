# MuNode 性能优化方案

## 1. 语音路由系统优化

### 1.1 当前状态分析

`VoiceRouter`（edge-server/src/voice/voice-router.ts）已经实现了事件驱动的缓存机制，但仍有优化空间。

#### 当前实现优点
- 使用 `routingCache` 缓存路由结果
- `serializedPacketCache` 避免重复序列化
- 事件驱动的缓存重建（`rebuildChannelCache`、`rebuildWhisperCache`）

#### 可优化点

**1.1.1 序列化缓存优化**

当前实现在发送语音包时会检查缓存大小并删除旧条目：

```typescript
// 当前实现（voice-router.ts:566-570）
if (this.serializedPacketCache.size > 1000) {
  const firstKey = this.serializedPacketCache.keys().next().value;
  this.serializedPacketCache.delete(firstKey);
}
```

**建议改进**：使用 LRU 缓存替代简单的 FIFO 删除

```typescript
// 推荐方案：使用 lru-cache 库
import { LRUCache } from 'lru-cache';

private serializedPacketCache = new LRUCache<string, Buffer>({
  max: 500,
  ttl: 1000, // 1秒TTL，语音包时效性很强
  updateAgeOnGet: false,
});
```

**预期收益**：
- 减少缓存未命中率
- 自动过期机制避免内存泄漏
- 更符合语音包访问模式

**1.1.2 varint 编码优化**

当前 `encodeVarint` 方法每次都创建新 Buffer：

```typescript
// 当前实现（voice-router.ts:997-1038）
private encodeVarint(value: number): Buffer {
  const i = value >>> 0;
  if (i < 0x80) {
    return Buffer.from([i]);
  }
  // ...更多分支
}
```

**建议改进**：预分配 Buffer 池

```typescript
// 推荐方案：Buffer 池化
class BufferPool {
  private pools: Map<number, Buffer[]> = new Map();
  
  acquire(size: number): Buffer {
    const pool = this.pools.get(size);
    if (pool && pool.length > 0) {
      return pool.pop()!;
    }
    return Buffer.allocUnsafe(size);
  }
  
  release(buffer: Buffer): void {
    let pool = this.pools.get(buffer.length);
    if (!pool) {
      pool = [];
      this.pools.set(buffer.length, pool);
    }
    if (pool.length < 100) { // 每个大小最多保留100个
      pool.push(buffer);
    }
  }
}
```

**预期收益**：
- 减少 GC 压力（语音包频率高）
- 减少内存分配开销

## 2. RPC 通信优化

### 2.1 批量 RPC 调用

当前 Hub-Edge 通信是逐条进行的，高频操作时会产生大量小包。

**当前问题**：
- `edge.reportSession` 每个用户一次调用
- `hub.userStateBroadcast` 每个状态变化一次广播
- 网络 RTT 累积影响性能

**建议改进**：批量 RPC 接口

```typescript
// protocol/src/rpc/rpc-types.ts 新增
export interface EdgeBatchReportSessionMethod {
  method: 'edge.batchReportSession';
  params: {
    sessions: Array<{
      session_id: number;
      user_id: number;
      username: string;
      edge_server_id: number;
      channel_id?: number;
      // ...其他字段
    }>;
  };
  result: {
    success: boolean;
    results: Array<{ session_id: number; success: boolean; error?: string }>;
  };
}

// Hub 端实现
async handleBatchReportSession(params) {
  const results = [];
  for (const session of params.sessions) {
    try {
      // 复用现有逻辑
      this._sessionManager.reportSession(session);
      results.push({ session_id: session.session_id, success: true });
    } catch (error) {
      results.push({ 
        session_id: session.session_id, 
        success: false, 
        error: error.message 
      });
    }
  }
  // 批量广播
  this.broadcast('hub.batchUserJoined', { sessions: params.sessions });
  return { success: true, results };
}
```

**预期收益**：
- 减少网络往返次数
- 降低 WebSocket 帧开销
- 批量操作可事务化

### 2.2 RPC 压缩

对于大型消息（如 fullSync），启用压缩可显著减少传输量。

```typescript
// 建议在 PacketCodec 中添加压缩支持
import { gzip, gunzip } from 'zlib';
import { promisify } from 'util';

const gzipAsync = promisify(gzip);
const gunzipAsync = promisify(gunzip);

const COMPRESSION_THRESHOLD = 1024; // 超过1KB启用压缩

async encode(packet: EdgeHubPacket): Promise<Buffer> {
  const data = packet.serialize();
  if (data.length > COMPRESSION_THRESHOLD) {
    const compressed = await gzipAsync(data);
    // 添加压缩标识头
    return Buffer.concat([Buffer.from([0x01]), compressed]);
  }
  return Buffer.concat([Buffer.from([0x00]), data]);
}
```

## 3. 数据库优化

### 3.1 连接与事务

当前 `HubDatabase` 使用单一连接，高并发时可能成为瓶颈。

**建议改进**：

```typescript
// 事务批量操作
async batchOperation<T>(
  operations: Array<() => Promise<T>>
): Promise<T[]> {
  await this.db.run('BEGIN TRANSACTION');
  try {
    const results = await Promise.all(operations.map(op => op()));
    await this.db.run('COMMIT');
    return results;
  } catch (error) {
    await this.db.run('ROLLBACK');
    throw error;
  }
}

// 使用示例：批量保存 ACL
async saveACLsBatch(channelId: number, acls: ACLData[]) {
  return this.batchOperation(
    acls.map(acl => () => this.addACL({ channel_id: channelId, ...acl }))
  );
}
```

### 3.2 查询优化

**3.2.1 频道层级查询**

`getChannelHierarchy` 当前使用循环查询：

```typescript
// 当前实现（database.ts:1350-1372）
async getChannelHierarchy(channel_id: number): Promise<number[]> {
  const hierarchy: number[] = [];
  let currentId = channel_id;
  while (currentId !== -1 && currentId !== null) {
    hierarchy.unshift(currentId);
    if (currentId === 0) break;
    const stmt = await this.db.prepare('SELECT parent_id FROM channels WHERE id = ?');
    const row = await stmt.get(currentId);
    // ...
  }
  return hierarchy;
}
```

**建议改进**：使用 CTE 递归查询（SQLite 3.8.3+）

```sql
-- 单次查询获取完整层级
WITH RECURSIVE channel_hierarchy AS (
  SELECT id, parent_id, 0 as depth
  FROM channels
  WHERE id = ?
  UNION ALL
  SELECT c.id, c.parent_id, ch.depth + 1
  FROM channels c
  JOIN channel_hierarchy ch ON c.id = ch.parent_id
  WHERE ch.parent_id > 0
)
SELECT id FROM channel_hierarchy ORDER BY depth DESC;
```

**3.2.2 权限计算缓存**

`HubPermissionChecker` 已经有缓存，但可以更激进：

## 5. 并发优化

### 5.1 消息处理并行化

当前消息处理是串行的，可以并行处理无依赖的操作：

```typescript
// 并行处理多个 UserState 更新（无依赖关系时）
async handleBatchUserState(updates: UserStateUpdate[]) {
  // 分组：按目标用户分组，同一用户的更新必须串行
  const groups = this.groupByUser(updates);
  
  // 不同用户的更新可以并行
  await Promise.all(
    Array.from(groups.entries()).map(([userId, userUpdates]) =>
      this.processUserUpdates(userId, userUpdates)
    )
  );
}
```

### 5.2 广播优化

当前广播遍历所有 Edge：

```typescript
// 建议：使用 Promise.allSettled 避免单个失败影响整体
async broadcastToEdges(method: string, params: any, excludeEdgeId?: number) {
  const promises = Array.from(this.edgeChannels.entries())
    .filter(([edgeId]) => edgeId !== excludeEdgeId)
    .map(([edgeId, channel]) =>
      channel.notify(method, params)
        .catch(err => {
          this.logger.error(`Broadcast to Edge ${edgeId} failed:`, err);
          return null; // 不阻塞其他 Edge
        })
    );
  
  await Promise.allSettled(promises);
}
```
