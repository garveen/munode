# MuNode 性能优化方案

## 1. 语音路由系统优化

### 1.1 当前状态分析

`VoiceRouter`（edge-server/src/voice/voice-router.ts）已经实现了事件驱动的缓存机制，但仍有优化空间。

#### 当前实现优点
- 使用 `routingCache` 缓存路由结果
- `serializedPacketCache` 避免重复序列化
- 事件驱动的缓存重建（`rebuildChannelCache`、`rebuildWhisperCache`）

#### 可优化点

**1.1.1 序列化缓存优化**

当前实现在发送语音包时会检查缓存大小并删除旧条目：

```typescript
// 当前实现（voice-router.ts:566-570）

  const firstKey = this.serializedPacketCache.keys().next().value;
  this.serializedPacketCache.delete(firstKey);

```

**建议改进**：使用 LRU 缓存替代简单的 FIFO 删除

```typescript
// 推荐方案：使用 lru-cache 库
import { LRUCache } from 'lru-cache';

private serializedPacketCache = new LRUCache<string, Buffer>({
  max: 500,
  ttl: 1000, // 1秒TTL，语音包时效性很强
  updateAgeOnGet: false,
});
```

**预期收益**：
- 减少缓存未命中率
- 自动过期机制避免内存泄漏
- 更符合语音包访问模式

## 2. RPC 通信优化

### 2.1 RPC 压缩

对于大型消息（如 fullSync），启用压缩可显著减少传输量。

```typescript
// 建议在 PacketCodec 中添加压缩支持
import { gzip, gunzip } from 'zlib';
import { promisify } from 'util';

const gzipAsync = promisify(gzip);
const gunzipAsync = promisify(gunzip);

const COMPRESSION_THRESHOLD = 2048; // 超过2KB启用压缩

async encode(packet: EdgeHubPacket): Promise<Buffer> {
  const data = packet.serialize();
  if (data.length > COMPRESSION_THRESHOLD) {
    const compressed = await gzipAsync(data);
    // 添加压缩标识头
    return Buffer.concat([Buffer.from([0x01]), compressed]);
  }
  return Buffer.concat([Buffer.from([0x00]), data]);
}

async decode(data: Buffer): Promise<EdgeHubPacket> {
  const isCompressed = data[0] === 0x01;
  const payload = data.slice(1);
  
  if (isCompressed) {
    const decompressed = await gunzipAsync(payload);
    return EdgeHubPacket.deserialize(decompressed);
  }
  return EdgeHubPacket.deserialize(payload);
}
```

**预期收益**：
- fullSync 等大消息传输量减少 60-80%
- 降低网络带宽占用
- 对小消息无额外开销

## 3. 数据库优化

### 3.1 查询优化

**3.1.1 频道层级查询**

`getChannelHierarchy` 当前使用循环查询：

```typescript
// 当前实现（database.ts:1350-1372）
async getChannelHierarchy(channel_id: number): Promise<number[]> {
  const hierarchy: number[] = [];
  let currentId = channel_id;
  while (currentId !== -1 && currentId !== null) {
    hierarchy.unshift(currentId);
    if (currentId === 0) break;
    const stmt = await this.db.prepare('SELECT parent_id FROM channels WHERE id = ?');
    const row = await stmt.get(currentId);
    // ...
  }
  return hierarchy;
}
```

**建议改进**：使用 CTE 递归查询

项目使用 `sqlite3@^5.1.7`，底层 SQLite 版本支持 CTE（3.8.3+），可以直接使用：

```typescript
async getChannelHierarchy(channel_id: number): Promise<number[]> {
  const query = `
    WITH RECURSIVE channel_hierarchy AS (
      SELECT id, parent_id, 0 as depth
      FROM channels
      WHERE id = ?
      UNION ALL
      SELECT c.id, c.parent_id, ch.depth + 1
      FROM channels c
      JOIN channel_hierarchy ch ON c.id = ch.parent_id
      WHERE ch.parent_id > 0
    )
    SELECT id FROM channel_hierarchy ORDER BY depth DESC
  `;
  
  const stmt = await this.db.prepare(query);
  const rows = await stmt.all(channel_id);
  return rows.map(row => row.id);
}
```

**预期收益**：
- 将 N 次查询减少为 1 次（N = 频道深度）
- 减少数据库连接开销
- 对于深层频道树效果更明显

## 5. 并发优化

### 5.1 消息分发并行化

当前 `ClientMessageRouter` 的多播和频道广播使用串行处理：

```typescript
// 当前实现（client-message-router.ts:165-169）
for (const sessionId of targetSessions) {
  if (!excludeSessions.has(sessionId)) {
    await this.sendToSession(sessionId, relay);
  }
}

// 频道广播同理（client-message-router.ts:194-198）
for (const sessionId of sessions) {
  if (!excludeSessions.has(sessionId)) {
    await this.sendToSession(sessionId, relay);
  }
}
```

**建议改进**：并行发送到不同 Edge

```typescript
// 推荐方案：按 Edge 分组后并行发送
private async handleMulticast(
  relay: hubedge.ClientMessageRelay,
  routing: hubedge.RelayRouting
): Promise<void> {
  const targetSessions = routing.target_sessions;
  const excludeSessions = new Set(routing.exclude_sessions);
  
  // 按 Edge 分组
  const sessionsByEdge = new Map<number, number[]>();
  for (const sessionId of targetSessions) {
    if (excludeSessions.has(sessionId)) continue;
    
    const session = this.sessionManager.getSession(sessionId);
    if (!session) continue;
    
    const edgeId = session.edge_id;
    if (!sessionsByEdge.has(edgeId)) {
      sessionsByEdge.set(edgeId, []);
    }
    sessionsByEdge.get(edgeId)!.push(sessionId);
  }
  
  // 并行发送到各个 Edge
  const promises = Array.from(sessionsByEdge.entries()).map(([edgeId, sessions]) =>
    this.sendToEdgeBatch(edgeId, relay, sessions)
      .catch(err => logger.error(`Failed to send to Edge ${edgeId}:`, err))
  );
  
  await Promise.allSettled(promises);
}
```

**预期收益**：
- 多 Edge 环境下显著降低广播延迟
- 单个 Edge 失败不阻塞其他 Edge
- 批量发送减少网络开销

### 5.2 Edge 广播优化

当前广播遍历所有 Edge：

```typescript
// 建议：使用 Promise.allSettled 避免单个失败影响整体
async broadcastToEdges(method: string, params: any, excludeEdgeId?: number) {
  const promises = Array.from(this.edgeChannels.entries())
    .filter(([edgeId]) => edgeId !== excludeEdgeId)
    .map(([edgeId, channel]) =>
      channel.notify(method, params)
        .catch(err => {
          this.logger.error(`Broadcast to Edge ${edgeId} failed:`, err);
          return null; // 不阻塞其他 Edge
        })
    );
  
  await Promise.allSettled(promises);
}
```
