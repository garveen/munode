# MuNode 架构建议

## 1. 现有架构评估

### 1.1 架构优点

| 方面 | 评价 | 说明 |
|------|------|------|
| **分布式设计** | ★★★★★ | Hub-Edge 架构支持水平扩展和地理分布 |
| **职责分离** | ★★★★☆ | Hub 管理，Edge 处理，分工清晰 |
| **协议兼容** | ★★★★★ | 完全兼容官方 Mumble 客户端 |
| **类型安全** | ★★★★☆ | TypeScript + Protobuf 提供良好的类型安全 |
| **模块化** | ★★★★☆ | pnpm workspace 多包管理 |

### 1.2 可改进点

| 方面 | 当前状态 | 建议 |
|------|----------|------|
| **状态一致性** | 最终一致 | 可接受，但需要更好的冲突解决 |
| **故障恢复** | 基本重连 | 需要更完善的断线重连和状态恢复 |
| **可观测性** | 基础日志 | 需要增加指标和追踪 |
| **测试覆盖** | 集成测试为主 | 需要增加单元测试和性能测试 |

## 2. Hub 架构建议

### 2.1 服务拆分考量

当前 Hub 是单体服务，如果需要更大规模，可考虑拆分：

```
                          ┌─────────────────┐
                          │   API Gateway   │
                          └────────┬────────┘
           ┌───────────────────────┼───────────────────────┐
           │                       │                       │
  ┌────────▼────────┐    ┌────────▼────────┐    ┌────────▼────────┐
  │  Auth Service   │    │ Channel Service │    │ Session Service │
  │ (认证、用户管理) │    │ (频道、ACL)     │    │ (会话、路由)    │
  └────────┬────────┘    └────────┬────────┘    └────────┬────────┘
           │                       │                       │
           └───────────────────────┼───────────────────────┘
                          ┌────────▼────────┐
                          │    Database     │
                          └─────────────────┘
```

**注意**：这是未来大规模扩展的方向，当前单体架构在中等规模下是合适的。

### 2.2 Hub 高可用

当前 Hub 是单点，可考虑以下方案：

**方案 A：Active-Passive**

```
┌──────────────┐     ┌──────────────┐
│  Hub Master  │◄────│  Hub Slave   │
│   (Active)   │     │  (Passive)   │
└──────┬───────┘     └──────────────┘
       │                     │
       │    ┌────────────────┘
       │    │ 故障切换
       ▼    ▼
    ┌──────────┐
    │  Edges   │
    └──────────┘
```

**实现要点**：
- 使用 SQLite WAL 或 Redis 同步状态
- 心跳检测 Master 存活
- Edge 配置多个 Hub 地址
- 自动切换时需要 Edge 重新注册

**方案 B：Multi-Active（复杂度高，未来考虑）**

```
┌──────────────┐     ┌──────────────┐
│    Hub 1     │◄───►│    Hub 2     │
│   (Active)   │     │   (Active)   │
└──────┬───────┘     └──────┬───────┘
       │                     │
       ▼                     ▼
┌──────────────┐     ┌──────────────┐
│   Edge A     │     │   Edge B     │
└──────────────┘     └──────────────┘
```

**挑战**：
- 需要分布式一致性协议
- 会话 ID 分配需要协调
- 复杂度显著增加

**推荐**：中短期采用方案 A，长期根据需求评估方案 B。

### 2.3 数据库策略

当前使用 SQLite，适合中等规模。扩展选项：

| 规模 | 数据库 | 说明 |
|------|--------|------|
| 小型（<1000用户） | SQLite | 当前方案，简单可靠 |
| 中型（1000-10000） | PostgreSQL | 更好的并发，读写分离 |
| 大型（>10000） | PostgreSQL + Redis | PG 持久化，Redis 缓存 |

**迁移路径**：

### 3.2 Edge 负载均衡

```
                 ┌─────────────────┐
                 │  Load Balancer  │
                 │ (DNS/L4/L7)     │
                 └────────┬────────┘
        ┌─────────────────┼─────────────────┐
        │                 │                 │
   ┌────▼────┐       ┌────▼────┐       ┌────▼────┐
   │ Edge 1  │       │ Edge 2  │       │ Edge 3  │
   │ (CN-BJ) │       │ (CN-SH) │       │ (US-W)  │
   └─────────┘       └─────────┘       └─────────┘
```

**负载均衡策略**：
- **地理就近**：根据客户端 IP 选择最近的 Edge
- **负载均衡**：选择负载最低的 Edge
- **能力匹配**：语音优先选择低延迟 Edge

**DNS 方式**：

```typescript
// Edge 注册时上报地理信息
await hubClient.call('edge.register', {
  server_id: config.server_id,
  name: config.name,
  host: config.network.externalHost,
  port: config.network.port,
  region: 'cn-beijing',  // 地区标识
  coordinates: { lat: 39.9, lon: 116.4 }, // 可选：精确坐标
});

// Hub 返回最佳 Edge
function selectBestEdge(clientInfo: ClientInfo): RegisteredEdge {
  const edges = this.registry.getEdgeList();
  
  // 按距离和负载综合排序
  return edges
    .filter(e => e.current_load < e.capacity * 0.9)
    .sort((a, b) => {
      const distA = this.calculateDistance(clientInfo.location, a.coordinates);
      const distB = this.calculateDistance(clientInfo.location, b.coordinates);
      const loadA = a.current_load / a.capacity;
      const loadB = b.current_load / b.capacity;
      
      // 综合评分：距离权重 0.7，负载权重 0.3
      return (distA * 0.7 + loadA * 0.3) - (distB * 0.7 + loadB * 0.3);
    })[0];
}
```

### 3.3 Edge 间语音路由优化

当前跨 Edge 语音通过 Hub 中转，可优化为直连：

```
当前：
Client A ──► Edge 1 ──► Hub ──► Edge 2 ──► Client B

优化后：
Client A ──► Edge 1 ───────────► Edge 2 ──► Client B
                   (UDP 直连)
```

**实现要点**（已部分实现）：

```typescript
// Edge 间 UDP 直连
interface EdgePeer {
  id: number;
  host: string;
  voicePort: number;
  quality: {
    rtt: number;
    packetLoss: number;
  };
}

// 语音路由决策
function routeVoice(targetEdgeId: number, packet: Buffer): void {
  const peer = this.peers.get(targetEdgeId);
  
  if (peer && peer.quality.rtt < 100) {
    // 直连发送
    this.udpSocket.send(packet, peer.voicePort, peer.host);
  } else {
    // 回退到 Hub 中转
    this.hubClient.notify('hub.relayVoice', { target: targetEdgeId, packet });
  }
}
```

### 4.3 RPC 超时和重试

```typescript
// 配置化的超时策略
const rpcTimeouts: Record<string, number> = {
  'edge.register': 10000,      // 注册需要更长时间
  'edge.fullSync': 30000,      // 全量同步可能很大
  'edge.heartbeat': 5000,      // 心跳应该快速返回
  'default': 15000,
};

const rpcRetryPolicy: Record<string, { maxRetries: number; backoff: 'linear' | 'exponential' }> = {
  'edge.heartbeat': { maxRetries: 3, backoff: 'linear' },
  'edge.fullSync': { maxRetries: 2, backoff: 'exponential' },
  'default': { maxRetries: 1, backoff: 'linear' },
};

async function callWithRetry<T>(method: string, params: any): Promise<T> {
  const timeout = rpcTimeouts[method] || rpcTimeouts['default'];
  const policy = rpcRetryPolicy[method] || rpcRetryPolicy['default'];
  
  let lastError: Error;
  
  for (let attempt = 0; attempt <= policy.maxRetries; attempt++) {
    try {
      return await this.call(method, params, timeout);
    } catch (error) {
      lastError = error;
      
      if (attempt < policy.maxRetries) {
        const delay = policy.backoff === 'exponential'
          ? 1000 * Math.pow(2, attempt)
          : 1000 * (attempt + 1);
        await sleep(delay);
      }
    }
  }
  
  throw lastError;
}
```

### 5.2 通用工具增强

```typescript
// common/src/utils/async.ts

/**
 * 带超时的 Promise
 */
export function withTimeout<T>(
  promise: Promise<T>,
  timeoutMs: number,
  message = 'Operation timed out'
): Promise<T> {
  let timeoutId: NodeJS.Timeout;
  
  const timeoutPromise = new Promise<never>((_, reject) => {
    timeoutId = setTimeout(() => reject(new Error(message)), timeoutMs);
  });
  
  return Promise.race([promise, timeoutPromise]).finally(() => {
    clearTimeout(timeoutId);
  });
}

/**
 * 指数退避重试
 */
export async function retryWithBackoff<T>(
  fn: () => Promise<T>,
  options: {
    maxRetries?: number;
    initialDelay?: number;
    maxDelay?: number;
    shouldRetry?: (error: Error) => boolean;
  } = {}
): Promise<T> {
  const {
    maxRetries = 3,
    initialDelay = 1000,
    maxDelay = 30000,
    shouldRetry = () => true,
  } = options;
  
  let lastError: Error;
  
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      lastError = error;
      
      if (attempt === maxRetries || !shouldRetry(error)) {
        throw error;
      }
      
      const delay = Math.min(initialDelay * Math.pow(2, attempt), maxDelay);
      await new Promise(r => setTimeout(r, delay));
    }
  }
  
  throw lastError!;
}

/**
 * 批量执行，控制并发
 */
export async function batchExecute<T, R>(
  items: T[],
  fn: (item: T) => Promise<R>,
  concurrency = 10
): Promise<R[]> {
  const results: R[] = [];
  const executing: Promise<void>[] = [];
  
  for (const item of items) {
    const p = fn(item).then(result => {
      results.push(result);
    });
    executing.push(p);
    
    if (executing.length >= concurrency) {
      await Promise.race(executing);
      executing.splice(executing.findIndex(p => p === p), 1);
    }
  }
  
  await Promise.all(executing);
  return results;
}
```

```typescript
// 连接速率限制
class ConnectionRateLimiter {
  private connections: Map<string, number[]> = new Map();
  
  canConnect(ip: string): boolean {
    const now = Date.now();
    const history = this.connections.get(ip) || [];
    
    // 清理超过1分钟的记录
    const recent = history.filter(t => now - t < 60000);
    
    if (recent.length >= 10) {  // 每分钟最多10次连接
      return false;
    }
    
    recent.push(now);
    this.connections.set(ip, recent);
    return true;
  }
}
```

### 7.3 认证强化

```typescript
// HMAC 认证增强
function validateHmacResponse(
  challenge: string,
  response: string,
  secret: string,
  maxAge: number = 60000  // 最大有效期 1 分钟
): boolean {
  // 从 challenge 中提取时间戳
  const [timestamp, nonce] = challenge.split(':');
  const challengeTime = parseInt(timestamp, 10);
  
  // 检查时间窗口
  if (Date.now() - challengeTime > maxAge) {
    return false;
  }
  
  // 验证 HMAC
  const expected = computeHmac(challenge, secret);
  return crypto.timingSafeEqual(
    Buffer.from(response, 'hex'),
    Buffer.from(expected, 'hex')
  );
}
```
