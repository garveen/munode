# MuNode 代码简化方案

## 1. 状态管理整合

### 1.1 当前问题

Edge Server 中存在多个状态管理组件，职责有重叠：

| 组件 | 文件 | 职责 |
|------|------|------|
| `EdgeStateManager` | state/state-manager.ts | 管理频道、ACL、封禁、远程用户追踪 |
| `ChannelManager` | models/channel.ts | 管理频道树结构、链接 |
| `ClientManager` | (通过factory访问) | 管理本地客户端、索引 |

**重叠点**：
- `EdgeStateManager.channels` 和 `ChannelManager.channels` 都存储频道数据
- 频道链接在两处都有维护
- 更新时需要同步两处

### 1.2 建议简化

**方案 A：EdgeStateManager 完全委托给 ChannelManager**

这是当前代码正在演进的方向（通过 `this.channelManager` 引用）。

```typescript
// EdgeStateManager 简化
export class EdgeStateManager {
  // 移除：private channels: Map<number, ChannelData> = new Map();
  // 移除：private channelTree: ChannelNode | null = null;
  // 移除：private channelLinks: Map<number, Set<number>> = new Map();
  
  private channelManager: ChannelManager; // 必须依赖
  private acls: Map<number, ACLData[]> = new Map();
  private bans: BanCache;
  private remoteUsers: ...;
  
  // 所有频道操作委托
  getChannel(channelId: number): ChannelData | undefined {
    const info = this.channelManager.getChannel(channelId);
    return info ? this.toChannelData(info) : undefined;
  }
  
  getAllChannels(): ChannelData[] {
    return this.channelManager.getAllChannels().map(this.toChannelData);
  }
}
```

**方案 B：合并为单一 StateManager**

```typescript
// 统一的状态管理器
export class UnifiedStateManager {
  // 频道管理
  private channels: Map<number, ChannelInfo> = new Map();
  private channelLinks: Map<number, Set<number>> = new Map();
  
  // 客户端管理（本地）
  private clients: Map<number, ClientInfo> = new Map();
  private clientIndexes: ClientIndexes;
  
  // 远程用户追踪
  private remoteUsers: RemoteUserTracker;
  
  // ACL 和封禁
  private acls: Map<number, ACLData[]> = new Map();
  private bans: BanCache;
  
  // 统一的事件发射
  // 便于其他组件订阅状态变化
}
```

**推荐**：方案 A，因为：
1. 改动较小
2. 保持职责分离（频道 vs 其他状态）
3. 当前代码已经在向这个方向演进

## 2. 消息处理器整合

### 2.1 当前结构

Edge Server 有多个消息处理器类：

```
packages/edge-server/src/handlers/
├── auth-handlers.ts      # 认证相关
├── channel-handlers.ts   # 频道操作
├── message-handlers.ts   # 文本消息、频道列表
├── state-handlers.ts     # 用户/频道状态
└── voice-handlers.ts     # 语音相关
```

这种分离是合理的，但存在一些问题：

1. **依赖注入繁琐**：每个 Handler 都需要通过 `HandlerFactory` 获取依赖
2. **跨 Handler 调用**：有时需要调用其他 Handler 的方法
3. **错误处理重复**：每个 Handler 都有类似的 try-catch 模式

### 2.2 建议改进

**2.2.1 统一错误处理装饰器**

```typescript
// 创建统一的错误处理包装器
function handleErrors(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value;
  
  descriptor.value = async function(...args: any[]) {
    try {
      return await originalMethod.apply(this, args);
    } catch (error) {
      const sessionId = args[0]; // 约定第一个参数是 session_id
      this.logger.error(`Error in ${propertyKey} for session ${sessionId}:`, error);
      // 可选：发送错误消息给客户端
    }
  };
  
  return descriptor;
}

// 使用示例
class AuthHandlers {
  @handleErrors
  async handleAuthenticate(session_id: number, data: Buffer) {
    // 具体逻辑，无需 try-catch
  }
}
```

**2.2.2 Handler 基类**

```typescript
abstract class BaseHandler {
  protected factory: HandlerFactory;
  protected logger: Logger;
  
  constructor(factory: HandlerFactory) {
    this.factory = factory;
    this.logger = factory.logger;
  }
  
  // 常用的便捷访问器
  protected get clientManager() { return this.factory.clientManager; }
  protected get channelManager() { return this.factory.channelManager; }
  protected get hubClient() { return this.factory.hubClient; }
  protected get config() { return this.factory.config; }
  
  // 通用方法
  protected sendPermissionDenied(sessionId: number, ...) { ... }
  protected sendReject(sessionId: number, ...) { ... }
}

// 具体 Handler 继承
class AuthHandlers extends BaseHandler {
  handleAuthenticate(session_id: number, data: Buffer) {
    // 直接使用 this.clientManager, this.hubClient 等
  }
}
```

## 3. RPC 类型系统简化

### 3.1 当前问题

`protocol/src/rpc/rpc-types.ts` 定义了大量的方法接口，类型推导复杂：

```typescript
// 当前：每个方法一个接口
export interface EdgeRegisterMethod { method: 'edge.register'; params: {...}; result: {...}; }
export interface EdgeHeartbeatMethod { method: 'edge.heartbeat'; params: {...}; result: {...}; }
// ... 30+ 个类似接口

// 然后组合
export type EdgeToHubMethods = EdgeRegisterMethod | EdgeHeartbeatMethod | ...;

// 再提取
export type RPCMethodMap = { [K in EdgeToHubMethods as K['method']]: K; };
export type RPCParams<M extends EdgeToHubMethods['method']> = RPCMethodMap[M]['params'];
```

### 3.2 建议简化

**方案：使用单一定义对象**

```typescript
// 统一的方法定义
export const rpcMethods = {
  'edge.register': {
    params: {} as {
      server_id: number;
      name: string;
      host: string;
      // ...
    },
    result: {} as RegisterResponse,
  },
  
  'edge.heartbeat': {
    params: {} as {
      server_id: number;
      stats: ServerStats;
    },
    result: {} as HeartbeatResponse,
  },
  
  // ... 其他方法
} as const;

// 类型提取
export type RPCMethods = typeof rpcMethods;
export type RPCMethodName = keyof RPCMethods;
export type RPCParams<M extends RPCMethodName> = RPCMethods[M]['params'];
export type RPCResult<M extends RPCMethodName> = RPCMethods[M]['result'];
```

**优点**：
- 定义和类型在一处
- 减少重复代码
- 更容易添加新方法
- IDE 智能提示更友好

### 3.3 Legacy RPC 清理

当前存在两套 RPC 系统：
- 新的 Protobuf-based（推荐）
- 旧的 TypedRPC（标记为 Legacy）

建议在确认新系统稳定后，逐步移除旧系统：

```typescript
// protocol/src/index.ts 中的注释
// Typed RPC (Legacy - will be deprecated)
export { TypedRPCClient, createTypedRPCClient } from './rpc/typed-rpc-client.js';
export { TypedRPCServer, createTypedRPCServer } from './rpc/typed-rpc-server.js';
```

## 5. 配置类型统一

- `edge-server/src/types.ts` - EdgeConfig
- `hub-server/src/types.ts` - HubConfig
- `common/src/types/` - 基础类型
- `protocol/src/` - 共享类型

## 6. 日志简化

### 6.1 当前问题

日志调用冗长：

```typescript
this.logger.info(`User ${username} connected from ${ip}`);
this.logger.debug(`Processing packet: type=${type}, size=${size}`);
```

### 6.2 建议改进

**结构化日志**

```typescript
// 定义日志事件类型
interface LogEvents {
  userConnected: { username: string; ip: string; sessionId: number };
  userDisconnected: { username: string; sessionId: number; reason?: string };
  voicePacketRouted: { from: number; to: number[]; size: number };
  rpcCall: { method: string; durationMs: number; success: boolean };
}

// 创建类型安全的日志器
class TypedLogger<Events extends Record<string, object>> {
  event<K extends keyof Events>(
    name: K, 
    data: Events[K], 
    level: 'info' | 'warn' | 'error' | 'debug' = 'info'
  ) {
    this.logger[level](`[${String(name)}]`, data);
  }
}

// 使用
const logger = new TypedLogger<LogEvents>();
logger.event('userConnected', { username: 'alice', ip: '1.2.3.4', sessionId: 1 });
```

## 8. 代码重复消除

### 8.1 权限检查模式

在多处存在类似的权限检查代码：

```typescript
// 当前：各处重复
if (this._permissionChecker) {
  const actorUserInfo = HubPermissionChecker.sessionToUserInfo(actorSession, actorSession.channel_id);
  const hasPermission = await this._permissionChecker.hasPermission(
    channelId,
    actorUserInfo,
    Permission.Write
  );
  if (!hasPermission) {
    // 处理拒绝
  }
}
```

**建议：提取通用方法**

```typescript
// hub-server/src/helpers/permission-helper.ts
export class PermissionHelper {
  constructor(
    private permissionChecker: HubPermissionChecker,
    private sessionManager: GlobalSessionManager
  ) {}
  
  async checkPermission(
    actorSessionId: number,
    channelId: number,
    permission: Permission
  ): Promise<{ allowed: boolean; actorSession?: GlobalSession; error?: string }> {
    const actorSession = this.sessionManager.getSession(actorSessionId);
    if (!actorSession) {
      return { allowed: false, error: 'Session not found' };
    }
    
    const actorUserInfo = HubPermissionChecker.sessionToUserInfo(actorSession, actorSession.channel_id);
    const allowed = await this.permissionChecker.hasPermission(channelId, actorUserInfo, permission);
    
    return { allowed, actorSession };
  }
}

// 使用
const { allowed, actorSession, error } = await this.permHelper.checkPermission(
  actorSessionId, channelId, Permission.Write
);
if (!allowed) {
  return { success: false, error };
}
```
