# MuNode 优化方案概述

## 1. 项目架构理解

MuNode 是一个基于 Node.js/TypeScript 的分布式 Mumble 服务器实现，采用 Hub-Edge 架构：

```
┌─────────────────────────────────────────────────────────────────┐
│                          Hub Server                              │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌────────────┐ │
│  │ AuthManager │ │ ACLManager  │ │ChannelMgr   │ │ Database   │ │
│  └─────────────┘ └─────────────┘ └─────────────┘ └────────────┘ │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐               │
│  │ SessionMgr  │ │ ControlSvc  │ │ VoiceTarget │               │
│  └─────────────┘ └─────────────┘ └─────────────┘               │
└───────────────────────────┬─────────────────────────────────────┘
                            │ WebSocket/RPC
              ┌─────────────┼─────────────┐
              │             │             │
    ┌─────────▼───────┐ ┌───▼───────────┐ ┌▼───────────────┐
    │  Edge Server 1  │ │ Edge Server 2 │ │ Edge Server N  │
    │  ┌───────────┐  │ │               │ │                │
    │  │ClientMgr  │  │ │               │ │                │
    │  │ChannelMgr │  │ │    (同上)      │ │    (同上)       │
    │  │VoiceRouter│  │ │               │ │                │
    │  │StateMgr   │  │ │               │ │                │
    │  └───────────┘  │ │               │ │                │
    └────────┬────────┘ └───────────────┘ └────────────────┘
             │
    ┌────────▼────────┐
    │ Mumble Clients  │
    │ (官方客户端兼容) │
    └─────────────────┘
```

### 各包职责

| 包名 | 职责 | 关键组件 |
|------|------|----------|
| **@munode/hub-server** | 中心管理节点 | AuthManager, ACLManager, ChannelManager, Database, ControlService |
| **@munode/edge-server** | 边缘处理节点 | ClientManager, VoiceRouter, MessageHandler, ClusterManager |
| **@munode/protocol** | 协议与通信 | Mumble Protobuf, RPC系统, WebSocket传输, 语音包处理 |
| **@munode/common** | 共享工具 | Logger, Config, Crypto(OCB2-AES128), HeartbeatManager |

## 2. 优化原则

### 2.1 不可变更的约束
- **Edge-Client 协议完全不变**：必须兼容官方 Mumble 客户端
- **Mumble 协议语义不变**：语音包格式、加密方式、消息类型
- **现有功能不可删除**：只能优化，不能破坏现有功能

### 2.2 优化目标优先级
1. **性能优化**：降低延迟、提升吞吐量、减少资源消耗
2. **代码简化**：减少重复、统一模式、提高可读性
3. **迭代友好**：便于扩展、测试友好、文档完善

| 类别 | 优化点 | 影响范围 | 优先级 |
|------|--------|----------|--------|
| 性能 | 语音路由缓存优化 | edge-server | 高 |
| 性能 | RPC 调用批量化 | protocol, hub-server | 中 |
| 性能 | 数据库连接池优化 | hub-server | 中 |
| 性能 | Protobuf 序列化池化 | protocol | 中 |
| 简化 | 状态管理统一 | edge-server | 高 |

| 简化 | RPC 类型系统简化 | protocol | 中 |
| 迭代 | 插件系统设计 | 全局 | 低 |
| 迭代 | 配置热更新 | common | 中 |
| 迭代 | 指标/监控增强 | 全局 | 中 |
